# Configuration Guide — OpenMRS CCE Receiver Adaptor

## Spring Profiles

| Profile | YAML file | Purpose |
|---------|-----------|---------|
| `default` | `application.yml` | Base config with sensible defaults |
| `local` | `application-local.yml` | Local dev — DEBUG logging, security disabled |
| `staging` | `application-staging.yml` | Pre-production — INFO logging |
| `production` | `application-production.yml` | Production — WARN root, security enabled |

```bash
./gradlew bootRun --args='--spring.profiles.active=local'
```

### Inbound API Security

| Property | Env Var | Default | Description |
|----------|---------|---------|-------------|
| `cce.security.enabled` | `CCE_SECURITY_ENABLED` | `false` | Enable inbound token validation |
| `cce.security.token` | `CCE_SECURITY_TOKEN` | — | Pre-shared bearer token (generated by adaptor, shared to CCE Intelligence Service for adaptor registration) |
| `cce.security.username` | `CCE_SECURITY_USERNAME` | `cce-client` | Basic auth username (fallback if token not set) |
| `cce.security.password` | `CCE_SECURITY_PASSWORD` | `changeme` | Basic auth password (fallback if token not set) |

The token filter in `SecurityConfig` checks only paths that start with `/api/`. It applies when `cce.security.enabled=true` and the token is not blank. The Beckn endpoints under `/beckn/**` are not checked by it, and `SecurityConfig` permits them explicitly (see below).

### Beckn

> **Status:** Built (demo), off by default. Full design: [beckn-integration.md](beckn-integration.md).

Turns on `POST /beckn/bpp-webhook/{action}` and `POST /beckn/bap-webhook/{action}`. Off by default. The existing `/api/v1/openmrs/fhir` endpoint is unchanged either way.

| Property | Env Var | Default | Description |
|----------|---------|---------|-------------|
| `receiver.beckn.enabled` | `OPENMRS_RECEIVER_BECKN_ENABLED` | `true` (on `demo-beckn`) | Turns both Beckn endpoints on. Off → they answer 404 |
| `receiver.beckn.onix.bpp-caller-url` | `OPENMRS_RECEIVER_BECKN_ONIX_BPP_CALLER_URL` | `http://onix-bpp:8082/bpp/caller` | `onix-bpp`'s caller, used to send `on_update` `ACCEPTED` to Spice |
| `receiver.beckn.self.bpp-id` | `OPENMRS_RECEIVER_BECKN_SELF_BPP_ID` | — (required) | OpenMRS's provider (BPP) id in the network registry |
| `receiver.beckn.self.bpp-uri` | `OPENMRS_RECEIVER_BECKN_SELF_BPP_URI` | — (required) | OpenMRS's provider address |
| `receiver.beckn.self.network-id` | `OPENMRS_RECEIVER_BECKN_NETWORK_ID` | empty | Optional. Put into `context.networkId` of the `on_update` when the request has none. A `networkId` in the request is copied over and wins |
| `receiver.beckn.spice.bap-id` | `OPENMRS_RECEIVER_BECKN_SPICE_BAP_ID` | — (required) | Spice's consumer (BAP) id. An `update` from any other `bapId` gets `Nack` (400) `BAD_REQUEST`. Any non-blank `message.contract.id` is accepted and echoed in `on_update` |
| `receiver.beckn.spice.bap-uri` | `OPENMRS_RECEIVER_BECKN_SPICE_BAP_URI` | — (required) | Spice's consumer address |
| `receiver.beckn.spice.referrals-in.commitment-file` | `OPENMRS_RECEIVER_BECKN_REFERRALS_IN_COMMITMENT_FILE` | `classpath:beckn/commitment-referral.json` | The commitment sent in `on_update`, and in a health-referral callback whose request has none. A JSON object with an `id`; read once at start |
| `receiver.beckn.health-id-types` | `OPENMRS_RECEIVER_BECKN_HEALTH_ID_TYPES` | empty | Health referrals: OpenMRS identifier type per patient health id system, `SYSTEM=type` pairs separated by `;` (e.g. `ABHA=national-id`). Without a pair the system is the type name, created on first use |

```yaml
receiver:
  beckn:
    enabled: ${OPENMRS_RECEIVER_BECKN_ENABLED:true}    # on by default on the demo-beckn branch
    onix:
      bpp-caller-url: ${OPENMRS_RECEIVER_BECKN_ONIX_BPP_CALLER_URL:http://onix-bpp:8082/bpp/caller}
    self:
      bpp-id: ${OPENMRS_RECEIVER_BECKN_SELF_BPP_ID:}                    # e.g. bpp.openmrs.example.org
      bpp-uri: ${OPENMRS_RECEIVER_BECKN_SELF_BPP_URI:}                  # e.g. https://openmrs.example.org/bpp/receiver
      network-id: ${OPENMRS_RECEIVER_BECKN_NETWORK_ID:}
    spice:
      bap-id: ${OPENMRS_RECEIVER_BECKN_SPICE_BAP_ID:}               # e.g. bap.spice.example.org
      bap-uri: ${OPENMRS_RECEIVER_BECKN_SPICE_BAP_URI:}             # e.g. https://spice.example.org/bap/receiver
      referrals-in:
        commitment-file: ${OPENMRS_RECEIVER_BECKN_REFERRALS_IN_COMMITMENT_FILE:classpath:beckn/commitment-referral.json}
    health-id-types: ${OPENMRS_RECEIVER_BECKN_HEALTH_ID_TYPES:}   # e.g. ABHA=national-id
```

The ids have no defaults. With `OPENMRS_RECEIVER_BECKN_ENABLED=true`, the default on the `demo-beckn` branch, the adaptor does not start when any of them is blank; the error names every missing setting. The example ids are made up. The "referrals in" ids must match the emitter's and Spice's settings.

**Security note.** `CCE_SECURITY_ENABLED` and `CCE_SECURITY_TOKEN` keep their meaning, for `/api/**` only. The Beckn endpoints are under `/beckn/**` because onix forwards the Beckn `Authorization: Signature …` header; under `/api/**` every Beckn message would get 401 whenever security is on. On `/beckn/**` the Beckn signature is checked by `openmrs-onix`, so keep these paths reachable only inside the OpenMRS network.

### OpenMRS Notifications (POST /alert)

Fire-and-forget user-facing alert pushed to OpenMRS after a successful **referral order** create. Surfaces in the OpenMRS 3 SPA bell + top-right toast via the **CCE Notifications** ESM. Failures never break the referral routing flow. See [openmrs-notification-integration.md](openmrs-notification-integration.md) for the wire contract.

| Property | Env Var | Default | Description |
|----------|---------|---------|-------------|
| `openmrs.notification.enabled` | `OPENMRS_NOTIFICATION_ENABLED` | `true` | Master switch — when `false`, no `POST /alert` is made |
| `openmrs.notification.expire-hours` | `OPENMRS_NOTIFICATION_EXPIRE_HOURS` | `48` | TTL written to `dateToExpire`; ESM hides expired alerts |
| `openmrs.notification.recipients.policy` | `OPENMRS_NOTIFICATION_RECIPIENTS_POLICY` | `static` | One of `role`, `static`, `role-or-static` |
| `openmrs.notification.recipients.role` | `OPENMRS_NOTIFICATION_RECIPIENTS_ROLE` | `Clinician` | Role name for the `role` lookup. **Note**: OpenMRS `/user?role=` does **not** filter server-side — all non-retired users come back |
| `openmrs.notification.recipients.static-uuids` | `OPENMRS_NOTIFICATION_RECIPIENTS_STATIC_UUIDS` | *(local admin uuid)* | Comma-separated OpenMRS **user** UUIDs (not person UUIDs). **MUST be overridden per environment** |
| `openmrs.notification.recipients.cache-ttl-seconds` | `OPENMRS_NOTIFICATION_RECIPIENTS_CACHE_TTL_SECONDS` | `300` | In-memory cache TTL for resolved recipient lists |
| `openmrs.notification.dedupe.ttl-hours` | `OPENMRS_NOTIFICATION_DEDUPE_TTL_HOURS` | `24` | Suppress duplicate alerts for the same `ServiceRequest.id` within this window |

**Severity** is derived from the inbound FHIR `ServiceRequest`, not configured:

| Signal | Result |
|---|---|
| `priority = stat` / `asap` | `CRITICAL` |
| `priority = urgent` | `WARNING` |
| else | `INFO` |
| **+** identifier value or `patientInstruction` contains `"high risk"` / `"critical"` / `"emergency"` | bumped one level (INFO→WARNING, WARNING→CRITICAL) |

Resolve user UUIDs with:

```bash
curl -s -u <user>:<pwd> \
  "$OPENMRS_REST_BASE_URL/user?v=custom:(uuid,display)" | jq
```

## Auto-Discovery

The following values are **auto-discovered** from OpenMRS at startup and do not need manual configuration. Override only if auto-discovery fails.

| Config | Discovered From | API Endpoint |
|--------|-----------------|-------------|
| Location UUID | Login Location tag | `GET /location?tag=Login+Location` |
| Identifier Type UUID | Matching `type-name` | `GET /patientidentifiertype` |
| Source Identifier Types | All non-primary types | `GET /patientidentifiertype` |
| Idgen Source UUID | Primary type source | `GET /idgen/identifiersource` |
| Visit Type UUID | "Facility Visit" preferred | `GET /visittype` |
| Encounter Types | All encounter types | `GET /encountertype` |
| Person Attribute Types | Phone Number, Email UUIDs | `GET /personattributetype` |

## Example: Local Development

```bash
SERVER_PORT=8080
OPENMRS_REST_BASE_URL=http://localhost:9096/openmrs/ws/rest/v1
OPENMRS_FHIR_BASE_URL=http://localhost:9096/openmrs/ws/fhir2/R4
OPENMRS_AUTH_TYPE=basic
OPENMRS_AUTH_USERNAME=admin
OPENMRS_AUTH_PASSWORD=Admin123
CCE_SECURITY_ENABLED=false
LOG_LEVEL_APP=DEBUG
# Notifications: set to a real OpenMRS user UUID for this environment
OPENMRS_NOTIFICATION_RECIPIENTS_STATIC_UUIDS=82f18b44-6814-11e8-923f-e9a88dcb533f
```


## Example: Production with OAuth2 (Outbound to OpenMRS)

```bash
# Outbound — OpenMRS auth via OAuth2
OPENMRS_AUTH_TYPE=oauth2
OPENMRS_AUTH_OAUTH2_TOKEN_URL=https://keycloak.example.org/realms/openmrs/protocol/openid-connect/token
OPENMRS_AUTH_OAUTH2_CLIENT_ID=cce-receiver-service
OPENMRS_AUTH_OAUTH2_CLIENT_SECRET=${SECRET_OAUTH2_CLIENT_SECRET}
OPENMRS_AUTH_OAUTH2_SCOPE=openid

# Inbound — pre-shared token for adaptor registration
CCE_SECURITY_ENABLED=true
CCE_SECURITY_TOKEN=${SECRET_CCE_TOKEN}

# OpenMRS endpoints
OPENMRS_REST_BASE_URL=http://openmrs:8080/openmrs/ws/rest/v1
OPENMRS_FHIR_BASE_URL=http://openmrs:8080/openmrs/ws/fhir2/R4
```

## Complete application.yml Reference

```yaml
server:
  port: 8080
  shutdown: graceful

spring:
  application:
    name: cce-receiver-adaptor
  lifecycle:
    timeout-per-shutdown-phase: 30s

cce:
  security:
    enabled: false
    token:                    # Pre-shared bearer token (from CCE_SECURITY_TOKEN env var)
    username: cce-client      # Basic auth fallback
    password: changeme

openmrs:
  rest:
    base-url: http://localhost:9096/openmrs/ws/rest/v1
    timeout: 10000
  fhir:
    base-url: http://localhost:9096/openmrs/ws/fhir2/R4
    timeout: 10000
  auth:
    type: basic
    username: admin
    password: Admin123
    oauth2:
      token-url:
      client-id:
      client-secret:
      scope:
  capability-refresh-ms: 21600000
  identifier:
    location-uuid:
    idgen-source-uuid:
    type-name: OpenMRS ID

management:
  endpoints:
    web:
      exposure:
        include: health,info,prometheus,metrics
  endpoint:
    health:
      show-details: when-authorized
      probes:
        enabled: true
  metrics:
    tags:
      application: cce-receiver-adaptor

logging:
  level:
    root: INFO
    org.openphc.cce: DEBUG
  pattern:
    console: "%d{ISO8601} [%thread] %-5level %logger{36} [%X{correlationId:-}] [%X{source:-}] [%X{resourceType:-}] - %msg%n"
```
